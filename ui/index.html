PHP extension

              
PHP talks to PostgreSQL with the pgsql and pdo_pgsql extensions (Laravel uses pdo_pgsql). The PHP builds Phlo downloads already include both, and Phlo turns them on in every php.ini, so there is nothing to add.

              
    
              
    Your databases live in the data folder above. A newer build of the same major version (18.6 to 18.7) keeps using them. A different major version (18 to 17, or 17 to 18) cannot open them. Phlo then stops PostgreSQL and tells you how to keep that folder and start with a new empty one. To move databases from one major version to another, copy them with pg_dumpall first (see docs/DEVELOPMENT.md).
    
              
    Add another build as runtime/postgres/17.11/bin/postgres.exe.

      User guide
      
          
      Phlo serves PHP sites from folders on this PC. The steps below are the ones you use from this dashboard.
      

          
      Start and stop
      
          
      Dark in the header switches the dashboard to dark mode. Light switches it back. The choice stays on this browser.
      
          
      Start in the header turns on Nginx and the PHP versions your sites need, plus each database and tool that is switched on in Settings. Stop turns those off and leaves this dashboard open. The Phlo window has the same Start and Stop. Minimize leaves Phlo running. Close leaves the dashboard running while the server is on. When the server is already stopped, Close also stops the dashboard.
      
          
      When a new Phlo release is published, a notice appears here. About → Update installs that release in one click. Your sites, databases, and downloaded servers stay on this PC.
      

          
      Add a site
      
          
        
            
      1. Open Projects.
        2. 
            
      2. Type a name such as inventory and press Add project.
        3. 
            
      3. Phlo creates home/inventory/public_html and serves it as inventory.test. A folder at subdomain/shop is shop.inventory.test.
        4. 
            
      4. Open the link on the card. When the HTTP port is not 80, the link includes that port, such as http://inventory.test:83/.
        5. 
          
      
          
      The first time, Windows may ask for approval to write the site names into the hosts file. Phlo only edits the block between # BEGIN PHLO and # END PHLO.
      

          
      PHP and the host name
      
          
      Each public_html and subdomain can use its own PHP. Use Change PHP on the project card. A version that is not installed can be downloaded from that dialog. An empty choice uses the default PHP in Settings.
      
          
      Host replaces inventory.test with a name such as myinventory.test. The name has to end with the TLD from Settings, which is test unless you changed it. Subdomains follow the new name. phpmyadmin.test is reserved.
      

          
      Add PHP or Redis by hand
      
          
      Settings → Runtimes can download a version. You can also copy a build into this Phlo folder. The folder name is the version. Reload the dashboard after you copy it. A folder is Installed only when the program Phlo runs is inside it, the same way a PHP folder is Installed only when php-cgi.exe is there.
      
          
      For PHP, extract a Windows PHP zip so php-cgi.exe and php.exe sit in runtime/php/8.4.3/, or one folder under that. runtime/php/8.4.3/php-cgi.exe and runtime/php/8.4.3/php-8.4.3-nts-Win32-vs17-x64/php-cgi.exe both count. Runtimes then lists that version as Installed, and Change PHP on a project can select it.
      
          
      For Redis, the folder has to contain redis-server.exe and the DLL files that came with that build. runtime/redis/8.10.2/redis-server.exe counts, and so does one extra folder from the zip, such as runtime/redis/8.10.2/Redis-8.10.2-Windows-x64-msys2/redis-server.exe. Choose that version under Settings → Redis, then press Start.
      
          
      A download named phpredis is the PHP extension, not the Redis server. Pasting that source into runtime/redis/6.1.0 leaves library.c and no redis-server.exe, so Phlo does not treat it as an installed Redis. The PHP builds Phlo downloads do not load that extension.
      

          
      Databases
      
          
      MariaDB is the MySQL server. The user is root with an empty password. After you download phpMyAdmin from Runtimes, it opens at phpmyadmin.test. PostgreSQL's first start creates the user postgres with no password. MongoDB has no user. Copy the .env block from Dashboard into your project. Phlo does not write that file for you.
      

          
      Check Redis and Memcached
      
          
      The Dashboard cards show whether Redis and Memcached are running, and the port on 127.0.0.1. The usual ports are 6379 and 11211. An application can use localhost for that address. If a card says stopped, download that program from Settings → Runtimes and press Start.
      
          
      On Windows, redis-cli is not on the system PATH. Typing redis-cli alone does not find it. From the Phlo folder, run the program in the version folder named on the Redis card. For Redis 8.10.2:
      
          
      .\runtime\redis\8.10.2\redis-cli.exe -h 127.0.0.1 -p 6379 PING
.\runtime\redis\8.10.2\redis-cli.exe -h 127.0.0.1 -p 6379 SET phlo:test hello
.\runtime\redis\8.10.2\redis-cli.exe -h 127.0.0.1 -p 6379 GET phlo:test
      
          
      PING answers PONG. GET answers hello. Use the version folder and the -p port from the card when they differ. On Linux the program is runtime/redis/8.10.2/redis-cli.
      
          
      Memcached does not include a separate client. From PowerShell, ask the port on the Memcached card for its version. This uses 11211:
      
          
      $tcp = New-Object System.Net.Sockets.TcpClient('127.0.0.1', 11211)
$tcp.Client.Send([Text.Encoding]::ASCII.GetBytes("version`r`n")) | Out-Null
$buf = New-Object byte[] 64
$n = $tcp.Client.Receive($buf)
[Text.Encoding]::ASCII.GetString($buf, 0, $n)
$tcp.Close()
      
          
      The reply starts with VERSION. On Linux, printf 'version\r\n' | nc 127.0.0.1 11211 does the same when nc is installed.
      
          
      The PHP builds Phlo downloads do not load the redis or memcached extensions, so php -m does not list them. A working redis-cli check does not by itself let every framework use Redis. Laravel can: copy the Redis block from Dashboard, which sets REDIS_CLIENT=predis, and point the host and port at the card. CodeIgniter 3's cache Redis driver needs the PHP redis extension. It reads app/config/redis.php (host, port, password). The $config['cache']['redis'] block in config.php is not that connection.
      

          
      Another PC, and port 80
      
          
      Sites open on this PC. To open them from a phone on the same network, choose this PC's address in Settings → Web server → Host IP and save. phpMyAdmin, the dashboard, and the databases stay on 127.0.0.1.
      
          
      If another program is using port 80, open the Phlo link that includes the port. Phlo leaves that program running.
      

          
      Mail, cron, and sharing
      
          
      Mailpit keeps mail on this PC. It does not send it. On Windows, Cron uses Cronical. When the Cron card says Cronical is not installed, press Download Cronical. Run test runs the example PHP command now and writes the output to this month's job log. Edit jobs is config/custom/cronical.dat: Minute, Hour, Day, Month, Weekday, then the command. Remove the # from a line to schedule it.
      
          
      Share on a project opens one ngrok tunnel after you save an authtoken under Settings → ngrok. HeidiSQL and SQLyog open MariaDB from the MariaDB card. They do not start with the stack.
      

          
      Terminal
      
          
      Terminal on a project opens a shell in that folder, and php there is the PHP selected for that folder. Settings → Toolchains can put Node.js, Python, Java, C++, and the Docker CLI on that PATH. Phlo does not run apps written in those languages, and it does not start a Docker engine.
      
        
      
      
      

      
      
        
      
          
      About Phlo
      
          
      Phlo 1.0.0
      
          
      First release
      
          
        
            
      • First public release.
        • 
            
      • Clone this repository, start Phlo, and download the servers you need from the dashboard.
        • 
            
      • Your sites, databases, and downloaded runtimes stay on your PC.
        • 
          
      
          
      You are up to date.
      
          
      
          
      Phlo is a personal, portable local development environment for Windows and Linux. It keeps the web server, PHP builds, Composer, configuration, and project folders inside this repository tree.
      
          
      Sites live under home/{account}/public_html (Settings can move the project folder) and open as {account}.test. Nginx, PHP pools, MariaDB, MongoDB, PostgreSQL, Redis, Memcached, and Mailpit listen on 127.0.0.1. The dashboard also binds to loopback. When you set a Host IP in Settings, Nginx also serves your projects on that address so other devices on your network can open them; phpMyAdmin, the dashboard, and the databases stay on 127.0.0.1.
      
          
      Node.js, Python, Java, and C++ are toolchains on the project Terminal PATH. Phlo does not start or proxy apps written in them.
      
          
      Docker is the CLI only. It connects to an engine already on this machine (Docker Desktop, WSL2, or a system dockerd). Phlo never installs or starts the engine.
